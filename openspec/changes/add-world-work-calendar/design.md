## Context

初始为空 Git 仓库；现已按用户确认的布局及 v0.3 配色实现正式应用、日历快照和部署工作流。实时交付状态见 docs/release-verification.md。数据源证据见 [调研](../../../docs/research.md)；所有数据源结论以调研日期 2026-10-24 为界，正式实施前复核。

## Goals / Non-Goals

目标：用一个页面回答“当地几点”“哪些关注地区在工作”“假日是否可能影响使用量”“北京时间什么时候重叠较多”。无后端、无需密钥、手机能用、后续新增地区低成本。

非目标：将工时推算成真实在线人数或流量预测；保证所有行业、企业、学校的作息一致；列举所有纪念日；自动抓取公司用户数据。

## Decisions

### 1. 信息架构与视觉方向

产品暂名“全球工作时钟 / World Hours”。首屏先回答两个问题：哪些关注地区处于工作时段、哪里有假日影响。用户反馈 v0.1 平铺时间轴和列表缺少焦点，因此 v0.2 改为单一主概览：白色主区域通过字号与留白突出工作国家数量和直接可读的国家名称，旁边用小面积低饱和琥珀色标识假日例外；完整时间轴下移为详细查询。

桌面（≥1100px）：标题和北京时间 → 主工作概览/假日提醒 → 默认收起的时间选择 → 各地时间详情/后续假日。概览明确部分城市工作的数量，不把样本当全国作息。点击国家可以定位并展开城市详情。详细列表按工作中、部分工作、假日、非工作排序，减少逐行寻找。

768–1099px：首屏仍保留工作与假日两个区域，下方详情单列。手机（<768px）：主概览内用三列紧凑国家入口，紧接着显示假日提醒；原本占首屏的日期和滑块收起为“查看其他时间”。390×844 默认样例首屏可同时看到全部 9 个工作地区和新西兰假日；国家更多时允许自然纵向延伸，不靠缩小字体塞满。用户无需先阅读时间轴才能知道当前概况。

### 视觉规范 v0.3（2026-10-24 最新要求）

用户保留 v0.2 信息层级，但明确否定大面积深蓝的颜色风格。正式应用 SHALL 使用以下银灰中性风格，不再沿用深蓝主卡或整块黄色提醒。

| 用途 | 色值 / 规范 |
| --- | --- |
| 页面背景 | 银灰 `#F5F5F7` |
| 主区域、提醒、列表 | 白色 `#FFFFFF`，细边 `#E4E4E7`，不使用装饰渐变或重阴影 |
| 主文字 | 炭黑 `#1D1D1F` |
| 次级文字 | 中灰 `#6E6E73`；正式正文不小于 12px |
| 唯一操作色 | 蓝色 `#0066CC`，用于链接、焦点、主按钮，不铺大面积背景 |
| 工作状态 | 深绿 `#257A56`，仅用于状态文字/小圆点，淡底 `#EEF5EF` |
| 假日状态 | 低饱和琥珀 `#8B672D`，淡底 `#F7F2E9`，提醒容器仍为白色 |
| 时间带 | 低饱和灰绿 `#A6B9B0`，指示线 `#565661` |
| 字体 | 系统 sans-serif（中文 PingFang SC / Microsoft YaHei 回退），时间用 tabular-nums |
| 层级 | 桌面概览标题约 32px、数字 44px；手机约 21px/32px；不靠大色块制造焦点 |
| 布局 | 页面上限 1440px，桌面边距 44px，手机 16px；区域间距 20–24px |
| 圆角 | 主区域 18px（手机 14px），国家入口 9px（手机 7px），控件 6–8px |

状态 SHALL 仍有文字，不只依赖颜色。层级来自标题大小、留白、国家名称和少量状态色。模拟标志与覆盖限制保持可见。此规范覆盖旧版海蓝/深蓝配色；截图仅用于评审，正式页面还需正常启动和线上验收。

主要交互：按工作中/假日/全部筛选；展开国家看代表地区；拖动统一北京时间轴；选择日期；回到现在；节日日历按国家筛选；设置关注地区、工作时段、周末与可选权重。空筛选说明无匹配结果并允许清除筛选。

设计复核：不使用世界地图占据首屏；首屏直接给出状态与国家名称，统一时间带保留为第二层信息。模拟模式与样例数据标记保持可见，焦点不依赖无依据的“高峰”判断。预览展示固定演示时间及样例假日，避免用动态时间造成设计评审截图内容不一致。

### 2. 工作状态模型

默认基准时区 `Asia/Shanghai`，显示北京时间及 UTC+8；查看者手机换时区不改变基准。每个地区必须配置有效 IANA 时区，不保存固定 UTC 偏移替代时区。以同一个 UTC instant，通过 `Intl.DateTimeFormat(..., { timeZone })` 提取目的地年月日、星期、小时和分钟；夏令时交由运行时 IANA 规则处理。

初始代表地区（明确为样本，不声称覆盖整个国家）：

| 国家/地区 | 首期代表地区与 IANA 时区 | 日历粒度 |
| --- | --- | --- |
| 中国 | 北京 Asia/Shanghai | 全国＋补班 |
| 俄罗斯 | 莫斯科 Europe/Moscow；加里宁格勒 Europe/Kaliningrad；叶卡捷琳堡 Asia/Yekaterinburg；新西伯利亚 Asia/Novosibirsk；符拉迪沃斯托克 Asia/Vladivostok | 全国＋生产日历调休；地区节日另标 |
| 马来西亚 | 吉隆坡 Asia/Kuala_Lumpur | 全国＋吉隆坡；其他州由用户添加 |
| 韩国 | 首尔 Asia/Seoul | 全国 |
| 美国 | 纽约 America/New_York；芝加哥 America/Chicago；丹佛 America/Denver；洛杉矶 America/Los_Angeles；安克雷奇 America/Anchorage；檀香山 Pacific/Honolulu | 联邦＋配置州，私人企业是否停工未知 |
| 新西兰 | 奥克兰 Pacific/Auckland | 全国＋所选地区周年日；查塔姆群岛可加 |
| 澳大利亚 | 悉尼 Australia/Sydney；墨尔本 Australia/Melbourne；珀斯 Australia/Perth | NSW / VIC / WA，不把州假日当全国假日 |
| 英国 | 伦敦 Europe/London | 英格兰与威尔士；苏格兰/北爱可添加，同一时区不同日历 |
| 日本 | 东京 Asia/Tokyo | 全国 |
| 新加坡 | 新加坡 Asia/Singapore | 全国 |
| 香港 | 香港 Asia/Hong_Kong | 地区公共假日 |
| 澳门 | 澳门 Asia/Macau | 地区公共假日；公共行政豁免不套用所有企业 |

默认工作日周一至周五，半开区间 `[09:00,18:00)`，不假设午休；设置支持多个非重叠时段，首期不支持跨午夜班次，输入需要明确校验。周末按地区可修改，不把所有国家统一锁死为周六日。

对某地区当地日期的判断顺序：经过来源核验的覆盖规则（显式工作日/休息日）→ 适用的公共假日 → 普通周末 → 普通工作日。覆盖记录须说明其替代了哪项来源；无明确优先关系的冲突标为待核实。确认补班后仍按该地区配置工时判断，并保留“调休上班”标签。补班不能简单被周末逻辑盖掉；中国长假中无名称的连休日也必须在静态数据中表示。

假日和时钟是独立维度：18:30 的公共假日仍显示假日；凌晨可以知道“不在设置工时内”，同时保留“假日数据待核实”。尚未取得日历时可显示“处于设置工时，日历待核实”，不得计为确定工作中。

国家汇总按**所配置代表地区**计算：全部确认工作 → 工作中；至少一个工作且另一个不工作/未知 → 部分工作（x/y 个代表地区，未知另列）；全部确认非工作 → 非工作；没有确定工作的地区且有可能工作的未知地区 → 待核实。不同原因通过地区展开显示，不笼统把部分州放假写为全国放假。

### 3. 工作覆盖程度与时间预测

默认所有国家等权，每国内代表地区等权。`a_i(t)` 为国家 i 在时间 t 确认处于工作中的代表地区占比，`u_i(t)` 为可能处于工作中但日历未知的占比。展示已确认覆盖下界 `Σ w_i a_i / Σ w_i`，有未知时同时显示上界 `Σ w_i(a_i+u_i)/Σ w_i`，不从分母中静默删除未知地区。

初始 `w_i=1`，默认文案“工作覆盖参考”，只反映选中样本的作息重叠，不是全球人口或产品流量。没有可靠国家权重时不显示“实际高峰”。若用户手工配置了用户分布权重，则可显示“加权工作覆盖估算”，同时显示权重来源、日期和样本限制。权重须非负、至少一个大于零，自动归一化；新增国家需要提示等权或补充权重。本次截图人数/百分比不写入代码、默认配置或公开产物。

未来 7 天按北京时间日期逐日构造 UTC 时间网格（15 分钟采样），每一个 instant 再映射到目的地日历，不直接加减固定时差。用于条形图及“工作重叠较多的时段”，不声称分钟级精度；查单点状态使用精确分钟。通过 instant 正向转换避开夏令时重复/不存在的本地时刻反解问题。

### 4. 节假日数据：开源生成＋官方校正＋可选接口

默认使用 MIT 许可的 `vacanza/holidays`（Python holidays），在开发机或 GitHub Actions 构建阶段生成年份 JSON，网页只读取同源静态文件。Python 不运行在浏览器中，也不需要常驻服务器。已锁定 holidays 0.107，保留 MIT 版权/许可声明；生成了 29 组地区日历并验证关键日期样例。

对 12 个国家/地区显式指定 `country/subdiv/years/observed/categories`，导出公共假日及实际补休日。中国/俄罗斯须另外导出工作日转移和补班记录，不能只把 holiday 字典序列化。对依赖未公布年度公告的日期标为 tentative/unverified。与官方年度日历抽查对齐后再提升覆盖等级。

Nager 免费 Community v4 保留为**个人使用可选适配器**，不作为首期必要依赖。官方条款明确允许 private projects；个人用于公司业务的认定和门户定义不清楚，不直接断言禁止。用户只自己查看的意图已记录。由于 MY/MO 数据缺口、CN/RU 调休不全、JP/SG 补休日遗漏，即使使用它也要有静态补充。v3 官方计划于 2027-01-31 结束服务，不选为长期依赖。可选适配器须映射 v4 的 `nationalHoliday/subdivisionCodes/holidayTypes`，UI 不直接依赖供应商字段。

马来西亚州假日、澳门假日适用人群、中国/俄罗斯年度工作日历等通过官方年度资料核验与校正；每条包含来源 URL、适用范围、发布日期/核验日期。英国 GOV.UK bank holidays JSON 是已实测无 key、可前端跨域调用的官方来源，可选直接请求或构建时合并。只认可明确的公共休假类别；纪念日、可选节日、仅公务员适用的补休不能自动当作全体用户停工。

首期实际模型按日存储，不额外维护日历事件与 manifest 两套文件：

- 顶层：schemaVersion、providerVersion、dataVersion（内容哈希）、generatedAt、reviewedThrough、calendars。
- 地区日历：countryCode、subdiv、scope、sourceUrl、rulesUrl、years。
- 年份：coverage（rule-based / projected）、days（当地 YYYY-MM-DD → name / originalName / kind）。
- kind：public-holiday（含连续休息日）或 working-day（补班）。同日冲突阻止生成。

`rule-based` 表示库在声明范围内的规则日历，不能等同全部官方逐日认证。2025/2026 按规则计算，已抽查关键日期；2027 保持 projected，工时内不能当作确定工作中。完整官方核验的进一步证据如未取得须如实说明。

加载策略：读取经过 schema 检查的本机快照，同时 fetch 同源 calendars.json（no-cache），8 秒超时。成功以 dataVersion 替换缓存；失败保留旧缓存并显示生成日期，没有缓存时仍可查看时间且日历未知。存储被禁用时保留内存数据，设置保存提示仅本次有效。提供手动重试，不为小型同源静态文件引入自动重试队列。

每周 Actions 只检查固定快照、关键日期及年度维护需求；数据更新需要更新依赖/官方补丁、审阅生成差异、提交后走正常 Pages 自动发布。尚未实现自动抓取官方公告或自动生成数据 PR，也不宣称永久自动更新。第三方 API 为未来可选适配，本期没有运行时外部请求或秘密。

### 5. 技术栈与部署

采用 Vite＋TypeScript＋React；用原生 CSS Grid/Flex 与 SVG 时间带，无需大型 UI/地图/图表依赖。时间转换先用原生 Intl，计算模块只接收 instant 与显式 zone，避免解析无时区日期字符串导致浏览器差异。预计模块：`config/regions`、`lib/time`、`lib/work-status`、`lib/holidays`、`data/calendars`、`components`。当前 preview 为单文件演示，正式实现不直接冒充其为生产逻辑。

设置用版本化 localStorage，校验 IANA ID、日期、工时范围、权重与 schemaVersion；存储被禁用时回退内存并明确提示设置不能保存。刷新实时状态每分钟一次，切回前台立即刷新；用户拖动时进入冻结的模拟模式，必须持续显示标记。以后可加配置 JSON 导入导出，首期不要求。

Pages 部署用 Actions：安装锁定依赖 → 静态类型/业务单测/构建 → 上传 `dist` → deploy-pages。配置项目仓库子路径 base；首期单页，不依赖服务器 rewrite，时间模拟状态使用 query（筛选仅内存），直接刷新不 404。资源相对 base 引用。发布权限限定 contents:read / pages:write / id-token:write，采用 Pages environment 和部署并发组。

使用当前目录及 Git 仓库，创建独立公开仓库 `zaizuole/world-work-clock`，配置 GitHub Actions 自动测试与 Pages 发布。用户已明确将建仓、代码、提交测试、自动发布及最终可用 URL 纳入交付，详见 docs/development-and-release.md。公开内容不含业务人数、凭据或截图原图。

无持续服务器费用。每周及手动 Actions 检查快照和年度维护，数据更新需人工审阅差异并提交；人工抽查官方年度资料。Actions 调度有延迟且不保证准点，公开仓库长期无活动还可能停用 schedule，不依赖它计算当前时间；可选 API 不可用时静态快照继续工作。新年数据尚未发布时保持待核实状态，提前检查不能保证得到下一年数据。

## Risks / Trade-offs

- 公共假日、地区周年日、企业休假和学生作息不同 → 显示适用范围和估算口径，不对“低使用量原因”作确定判断。
- 代表地区并非国家用户的真实分布 → 展示所选城市与样本数量；后续有可靠分布再配置权重。
- 中国/俄罗斯调休及马来西亚/澳门覆盖不足 → 必须维护静态数据，缺失明确标注；这是首期主要数据风险。
- 浏览器时间和时区数据库可能过旧 → 显示基于设备时间，避免承诺服务器校时；运行环境支持矩阵纳入验收。
- 静态托管没有私有设置同步 → 各浏览器独立，换设备需要重设。站点公开，但浏览器本地设置默认不上传。

## Validation Plan

业务模块针对北京时间跨日、目的地跨年、09:00/18:00 边界、美国/英国/澳洲夏令时、仅某州放假、周末补班、连续休假、未知日历、零权重和部分地区工作做有意义单测。

浏览器验收覆盖 1440×1000、768×1024、390×844、360×800；包含首屏、筛选、展开、日期与时间模拟、回到现在、设置持久化、API 失败和缓存。键盘可操作，控件命中区至少 44px、可见焦点，文字对比度达到 WCAG AA，支持减少动画。

在正式本地应用及 Pages 实际地址各执行桌面/手机验收并截图，区分视觉、交互、真实接口覆盖；独立设计预览只验证布局方向。数据源单独采样核对官方日历，接口返回成功不等于调休语义正确。

## Migration / Rollback

新项目没有旧业务迁移。设置 schema 升级保留可兼容字段，损坏时提示重置。发布失败保留上一静态部署；数据异常回退前一经核验数据版本，在覆盖状态中展示限制，不清除用户配置。

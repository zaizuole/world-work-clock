# 日历数据维护

## 已实现的默认路线

使用 Python holidays 0.107（MIT）和仓库内中文名称映射，生成同源 `public/data/calendars.json`。浏览器不依赖第三方 API、不携带密钥；Nager 是调研保留选项，本期未接入。

快照按国家/地区、年份存储，事件类型为 `public-holiday`（包括连续休息日）或 `working-day`。中国周末补班从库的 `weekend_workdays` 单独导出；生成时若出现工作/休假冲突立即失败。`observed=True` 保留补休。

- 2025、2026：`rule-based`，代表数据库覆盖的规则日历，已抽查关键日期，不是每一天的官方认证。
- 2027：`projected`，允许在列表查看预测假日，但工作判断保留待核实。
- 不存在的国家/地区/年份：未知，不能当作无假日。

每份区域日历包含地区代码、适用口径、资料来源和规则源码链接；顶层记录提供者版本、内容哈希版本与生成时间。俄罗斯当前主要使用全国规则，未覆盖共和国额外假日；澳门默认只取强制性假日；马来西亚、美国、澳大利亚、英国、新西兰按选择的地区匹配。

## 更新步骤

```sh
pip install -r scripts/requirements.txt
python scripts/generate_calendars.py --year 2026
python scripts/check_calendars.py
npm run check
```

检查快照差异后提交、推送，由 Pages 工作流自动发布。升级库时应一起更新 requirements、版本断言和许可；查看取消/新增/改期、地区范围和补班，不只看条目数。

核验新年份时：收集官方年度公告，重点核对 CN/RU 调休、MY 州规则、MO 适用人群和 observed 日期；更新 `REVIEWED_THROUGH`，调整生成基准年、日期样例和工作流中的固定年份，并审阅快照。**不要只把年份数字向后加就宣称完成数据核验。**

每周的 `calendar-check.yml` 仅做快照和年度维护检查；当前年份超出规则核验范围时失败提示维护。GitHub schedule 可能延迟，公开仓库长期无活动可能停用，所以还保留手动触发，不能把它视为永久自动更新承诺。

## 缓存与失败

浏览器先用经过校验的本机快照，再请求同源 JSON（`cache: no-cache`，8 秒超时）。成功后按数据版本替换；失败保留本机快照并显示缓存提示。无有效缓存时仍能看时钟，工时内状态待核实。禁止 localStorage 时使用内存，设置保存会明确提示。

## 已检查样例及边界

- 中国 2026 年 6 个补班日与 10 月 7 日连续休假：国务院公告。
- 日本 2026-05-06、09-22：内阁府替代/夹日休日。
- 新加坡 2026-11-09、马来西亚吉隆坡 06-02：标准周末补休安排。
- 俄罗斯 01-09、05-11、12-31：库与生产日历样例；俄罗斯官方公告未逐条独立核验。
- 澳大利亚 VIC 11-03 与 NSW 差异、新西兰 10-26、澳门 10-01 与非公务员补休口径。

这些样例验证是回归保障，不构成所有年份和所有企业日历的准确性承诺。来源索引见 `research.md`。
